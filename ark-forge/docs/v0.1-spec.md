# ARK Forge v0.1 Specification

**Goal:** Engineering workbench — runtime capabilities + Flutter views.

## Architecture rule

**Flutter is UI. Forge Runtime owns the machine.**

Flutter must not invoke git, inspect processes, launch terminals, or read engineering files directly.

## Forge Runtime v0.1 capabilities

| Capability | API |
|------------|-----|
| Read Engineering Authority | `GET /api/v1/state`, `GET /api/v1/engineering/docs/{slug}` |
| Git observe | included in `/api/v1/state` |
| Launch Cursor | `POST /api/v1/workspace/open` `{ "target": "cursor" }` |
| Launch browser | `{ "target": "browser" }` |
| Launch terminal | `{ "target": "terminal" }` |
| Open GitHub | `{ "target": "github" }` |
| Read filesystem | doc endpoints |
| Watch files | runtime internal (notify) — refresh UX in v0.1.1 if needed |
| Settings | `ARK_FORGE_REPO_PATH`, `ARK_FORGE_PORT` env |

## Flutter v0.1

Views only:

- Workbench dashboard (milestone, PR, git, review, architecture)
- Engineering authority doc viewer
- Workspace buttons → runtime API

## Dashboard projection fields

| Field | Source |
|-------|--------|
| Current Milestone | runtime reads `CURRENT_MILESTONE.md` |
| Active PR | runtime reads `ACTIVE_PR.md` |
| Git | runtime via libgit2 / git |
| Recent Review | runtime reads `reviews/` |
| Architecture | Frozen when `ARCHITECTURE.md` exists |

## Out of scope (v0.1)

- AI chat
- MCP
- Multi-agent orchestration
- Cursor API integration
- Test runner / Docker
- Runtime storing engineering truth
- Flutter calling git or OS directly

## Definition of done

- [ ] Runtime serves `/api/v1/state` from repo
- [ ] Flutter renders state via HTTP only
- [ ] Workspace actions go through runtime
- [ ] No engineering authority writes
- [ ] No Flutter direct git/process/filesystem for engineering data
