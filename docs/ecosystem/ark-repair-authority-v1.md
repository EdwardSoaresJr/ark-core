# Repair Authority v1

**Status:** Platform doctrine — convergence of Authority vs Projection, Pressure First, Earned Authority, and public Growth knowledge  
**Not:** A CMS model, a nav rename, or permission to retitle `CommonProblem*` in code  
**Applies to:** Public problem/service pages · advisor guidance · future AI / Voice explanations of repairs

---

## Principle

**The repair is the authority.**

Problems, services, advisor guidance, and future AI interactions are **projections** of the same operational truth.

A repair authority exists to accumulate knowledge earned through real shop operations.

> **Repair Authority describes what the shop knows. Projections describe how different audiences experience that knowledge.**

**Test:** If the information should improve every representation of that repair, enrich the authority. If it only exists to satisfy one page or audience, it is a projection.

---

## Authority lifecycle

```text
Operational Truth
        ↓
Observation
        ↓
Authority
        ↓
Projection
        ↓
Multiple Projections
        ↓
Rename
```

**Vocabulary follows behavior.**

A broader name is earned only after multiple projections depend on the same authority.

**A rename is a projection, too.** Mental model can change first. URLs, tables, classes, and navigation follow only when multiple parts of the system require the broader vocabulary.

---

## Projections

A single repair authority may project as:

| Projection | Audience question |
| --- | --- |
| **Problem view** | What's wrong? |
| **Service view** | Can you fix it? |
| **Advisor view** | How do I explain it? |
| **Future AI / Voice** | How do we speak this truth? |

Each projection serves a different audience. **None owns truth.**

---

## Operational feedback

Repair Orders enrich authorities — not authored marketing copy.

```text
Concern
    ↓
Diagnosis
    ↓
Repair Performed
    ↓
Outcome
    ↓
Repair Authority
```

Authorities become more accurate through completed work.

## Current state

| Layer | Decision |
| --- | --- |
| **Doctrine** | Repair Authority is the conceptual spine |
| **Public** | Continue `/common-problems/` and current navigation |
| **Implementation** | `CommonProblem*` remains the implementation vocabulary until multiple projections read the **same** authority record — not a parallel config |

No implementation rename is planned before that condition is met.

---

## Engineering rule

Do **not** rename code, URLs, tables, or navigation because a broader name sounds better.

Rename **only** when multiple projections share the same underlying authority.

Until then, the code is allowed to lag the doctrine. That is not debt — it is honesty.
