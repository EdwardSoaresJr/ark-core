# ARK Self-Signed Printing Feasibility Pass

**Goal:** Determine whether ARK can use an ARK-owned certificate chain with **unmodified stock QZ Tray** binaries.

**Scope:** Certificate ownership only. No QZ fork, no QZ source changes, no custom tray builds, no printing workflow changes.

**Status:** Feasible for development proof-of-concept. Production rollout requires per-workstation root trust (or QZ Site Manager whitelist), not server deploy alone.

---

## Executive summary

| Question | Answer |
|----------|--------|
| Can stock QZ Tray silent-print with ARK-issued certs? | **Yes**, when ARK Root CA is trusted on the workstation via `override.crt`, `authcert.override`, or Site Manager whitelist — plus server-side signing via existing `QzTraySigning`. |
| Can existing ARK sign-message infrastructure be reused? | **Yes.** `QzTraySigning`, `POST /app/api/qz/sign-message`, and `print-helpers.blade.php` already implement the official QZ pattern (`setCertificatePromise` + `setSignaturePromise` + SHA512). |
| Commercial QZ certificate required? | **No** for proof-of-concept. Commercial certs are pre-trusted by QZ’s embedded root; ARK-owned certs replace that trust with ARK Root CA on each workstation. |
| Blockers found? | Workstation trust distribution (not PHP signing). ARK must install `override.crt` (or equivalent) on every print workstation. |

**Recommendation:** Proceed with ARK-owned certificate ownership. Do **not** fork QZ Tray. Use dev scripts in `infra/qz-dev/` to generate certs, prove signing locally, then define a shop workstation trust playbook before production.

---

## How stock QZ Tray trusts certificates

QZ Tray ships with a **built-in trusted root** used for commercial certificates issued through the QZ portal. That root is **not** ARK-owned.

For ARK-owned chains, stock QZ (2.1+) supports replacing or augmenting trust **without modifying QZ source**:

| Mechanism | Platform | What to install |
|-----------|----------|-----------------|
| `override.crt` in QZ install dir | Windows / macOS / Linux | ARK Root CA PEM (`infra/qz-dev/certs/override.crt`) |
| `authcert.override=/path/to/root.crt` in `qz-tray.properties` | All | Same ARK Root CA |
| `java -DtrustedRootCert=override.crt -jar qz-tray.jar` | All | Same ARK Root CA |
| Site Manager → Create New (demo-style) | Per machine | Machine-local only; not suitable for fleet |
| `java -jar qz-tray.jar --allow cert.pem` | All | Whitelist leaf or root into `allowed.dat` |

Official references:

- [QZ Signing](https://qz.io/docs/signing) — `setCertificatePromise`, `setSignaturePromise`, SHA512, PKCS#8 2048-bit key
- [QZ Command Line](https://qz.io/docs/command-line) — `--allow`, `trustedRootCert`
- [QZ Generate Certificate](https://qz.io/docs/generate-certificate) — commercial portal flow (what we are **not** adopting)

**Critical insight:** The browser presents the **leaf signing certificate** (`digital-certificate.txt`). QZ validates that it chains to a **trusted root** (commercial QZ root **or** ARK Root CA via `override.crt`). The server holds the **private key** and signs each privileged QZ API call.

## Required certificate hierarchy

ARK development chain (generated by `infra/qz-dev/generate-ark-printing-certs.sh`):

```
ARK Root CA                    (self-signed, CA:true, keyCertSign)
    └── ARK Printing Signing   (end-entity, digitalSignature + keyEncipherment)
```

An intermediate CA is **optional** for ARK. A two-level hierarchy is sufficient for a single shop. Add an intermediate later if you need rotation without re-trusting a new root on workstations.

| Role | File (dev) | Used where |
|------|------------|------------|
| ARK Root CA | `ark-root-ca.crt.pem` / `override.crt` | QZ Tray workstation trust only |
| ARK Root CA private key | `ark-root-ca.key.pem` | **Offline only** — never on web server |
| Signing leaf cert | `digital-certificate.txt` | Browser `setCertificatePromise` (injected by Laravel) |
| Signing private key | `private-key.pem` | Server `QZ_PRIVATE_KEY_PATH` only |

## Certificate attributes QZ requires (verified)

Based on QZ official docs, GitHub issues ([#799](https://github.com/qzind/tray/issues/799)), and local `verify-ark-printing-certs.sh` output:

| Requirement | QZ expectation | ARK dev script output |
|-------------|----------------|------------------------|
| Key algorithm | RSA **2048-bit** | 2048-bit RSA |
| Private key format | **PKCS#8** PEM (`private-key.pem`) | `openssl pkcs8 -topk8 -nocrypt` |
| Private key encryption | Unencrypted for PHP server signing | Unencrypted |
| Public cert format | X.509 PEM (`digital-certificate.txt`) | Leaf PEM |
| Signature algorithm | **SHA512** (QZ 2.1+) | `QZ_SIGNATURE_ALGORITHM=sha512` default in ARK |
| Leaf key usage | Signing / encipherment (not CA) | `digitalSignature`, `keyEncipherment` |
| Root key usage | CA signing | `keyCertSign`, `cRLSign`, `CA:TRUE` |
| Organization name | Was required historically; **no longer required** per QZ 2.1.3+ | Set to `Auto Repair Keeper` |
| FQDN in CN | Helpful for Site Manager; not strict for override-root model | Configurable via `ARK_PRINTING_CN` |
| Intermediate PEM marker | Legacy `--START INTERMEDIATE CERT--` was non-standard; modern QZ accepts concatenated PEM chain | Chain file provided; leaf-only also works with `override.crt` |
| Extended key usage | Not documented as strict | `codeSigning`, `clientAuth` on leaf (conservative) |
| Expiration | Commercial certs renewed via QZ portal | Dev leaf ~27 months; root ~10 years |

## Existing ARK infrastructure audit

### Reusable as-is

| Component | Path | Role |
|-----------|------|------|
| `QzTraySigning` | `app/Ark/Operations/Printing/QzTraySigning.php` | Loads PEM paths from env, `openssl_sign` SHA512, injects cert into Blade |
| `QzTraySignController` | `app/Ark/Operations/Printing/QzTraySignController.php` | `POST /app/api/qz/sign-message` → `{ signature }` |
| Print bootstrap | `resources/views/components/operations/print-helpers.blade.php` | `setCertificatePromise` + fetch signer to sign-message |
| Config | `config/printing.php` | `QZ_CERTIFICATE_PATH`, `QZ_PRIVATE_KEY_PATH`, `QZ_SIGNATURE_ALGORITHM` |
| Health | `GET /app/api/qz/sign-health` | Round-trip sign/verify self-test |

### End-to-end flow (unchanged)

```
Browser (ARK page)
  → setCertificatePromise(leaf PEM from server)
  → qz.websocket.connect()
  → QZ Tray validates cert against trusted root (override.crt = ARK Root)
  → qz.print() / other signed calls
  → setSignaturePromise hashes payload
  → POST /app/api/qz/sign-message { data }
  → QzTraySigning::signBase64 (openssl_sign SHA512)
  → QZ Tray verifies signature with leaf public key
  → Silent print (no prompt)
```

**No code changes are required** to swap commercial QZ certs for ARK-generated certs — only env paths and workstation trust.

### Not in scope / unchanged

- Shop settings (`shop_settings`) — printer names, label dimensions only; certs stay in env
- QZ Tray binary — stock install from qz.io
- Print PDF pipeline — Brother QL raster path unchanged

## Workstation trust requirements

Silent printing fails if the workstation does not trust ARK Root CA, even when server signing is perfect.

### Windows

1. Generate dev certs: `bash infra/qz-dev/generate-ark-printing-certs.sh`
2. Copy `infra/qz-dev/certs/override.crt` to QZ Tray install folder, e.g. `C:\Program Files\QZ Tray\override.crt`
3. Restart QZ Tray (system tray → Exit, then relaunch)
4. Alternative: import `ark-root-ca.crt.pem` into **Local Computer → Trusted Root Certification Authorities** (group policy / installer script for fleet)

### macOS

1. Copy `override.crt` to `/Applications/QZ Tray.app/Contents/Resources/override.crt` (path may vary by QZ version)
2. Or set `authcert.override` in `qz-tray.properties`
3. Restart QZ Tray
4. Alternative: add ARK Root CA to System keychain as trusted root

### Linux

1. Place `override.crt` beside QZ Tray JAR / install directory
2. Or `authcert.override=/path/to/ark-root-ca.crt.pem` in `qz-tray.properties`
3. Restart `qz-tray` service or user session
4. Alternative: `java -jar qz-tray.jar --allow /path/to/ark-root-ca.crt.pem`

### Fleet operations note

For one repair shop, trust installation is a **one-time per workstation** procedure (similar to installing QZ Tray itself). Document in shop runbook; do not bake root private keys into installers.

Outputs (gitignored except `.gitkeep`):

```
infra/qz-dev/certs/

  ark-root-ca.key.pem      # OFFLINE ONLY
  digital-certificate.txt  # Leaf → QZ_CERTIFICATE_PATH

QZ_CERTIFICATE_PATH=infra/qz-dev/certs/digital-certificate.txt
QZ_PRIVATE_KEY_PATH=infra/qz-dev/certs/private-key.pem
QZ_SIGNATURE_ALGORITHM=sha512
```

## Local proof-of-concept

### 1. Server signing (no QZ Tray required)

```bash
php artisan tinker --execute="dump(App\Ark\Operations\Printing\QzTraySigning::healthSnapshot());"
php artisan tinker --execute="dump(App\Ark\Operations\Printing\QzTraySigning::selfTestSigningRoundTrip());"
```

Expect `ready: true` and self-test `true`.

### 2. Browser + stock QZ Tray (full POC)

1. Install stock QZ Tray from [qz.io](https://qz.io/download/)
2. Install `override.crt` on the workstation (see above)
3. Point local `.env` at dev certs
4. Log into ARK locally, visit **`/dev/qz-poc`** (local environment only)
5. Click **Connect** — log should show certificate accepted and signed `getVersion` call
6. Optional: open a repair order with `:printing="true"` and print a key tag

Success criteria: QZ connects without “untrusted website” blocking signed calls; sign-message returns 200; print proceeds without Allow dialog.

### 3. Health endpoint

As a user with `settings.manage`:

`GET /app/api/qz/sign-health` → `{ "status": "ok", "algorithm": "SHA512", ... }`

## Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| Workstation trust not installed | High | Shop playbook + installer script; POC checklist per machine |
| Root CA private key on web server | Critical | Only leaf key on server; root key stays offline |
| Leaf cert expiry | Medium | Calendar reminder; re-run generator; redistribute leaf + override unchanged if same root |
| Advisor uses machine without QZ | Low | Existing `ARK_QZ_MODE=dev` fallback with prompts |
| macOS QZ path differences | Medium | Verify path per QZ version during pilot |
| Confusion with commercial QZ certs | Low | This doc; keep ARK paths separate from legacy ARK-SMS `/qz/*.pem` references |

## Why not fork QZ Tray?

| Approach | Maintenance | Outcome |
|----------|-------------|---------|
| ARK cert + stock QZ | Low — OpenSSL + env + workstation trust | **Recommended** |
| Fork QZ Tray | High — Java desktop releases, security patches | Unnecessary |
| Commercial QZ cert only | Medium — recurring cost, QZ portal dependency | Valid but not ARK-owned |
| Client-side JS signing | Security risk — private key in browser | Rejected by QZ and ARK |

## Production migration path (if POC succeeds)

1. **Pilot** — One advisor workstation with `override.crt` + dev certs pointed at staging/local
2. **Generate production pair** — Separate script invocation with production OU/CN; store PEMs on VPS outside `public/` (see `docs/printing/qz-certificate-investigation.md` paths)
3. **Env** — `QZ_CERTIFICATE_PATH` / `QZ_PRIVATE_KEY_PATH` on shared `.env`
4. **Workstation rollout** — Install same ARK Root CA on each print PC (MSI/script/keychain profile)
5. **Verify** — `GET /app/api/qz/sign-health` on production; print key tag on each machine
6. **Rotation** — Reissue leaf cert from offline root; root rotation requires re-trust on workstations

Do **not** copy `infra/qz-dev/certs/` to production verbatim — generate a production-specific pair.
