# Design Reference Library

This reference library exists ONLY for operational UX grounding.

ARK is currently in the Core Operational Foundation Phase.

Study only core daily shop operations:

- queue
- dashboard
- repair orders
- estimate workflow
- approvals
- customer workflow
- vehicle workflow
- technician workflow
- parts/procurement basics
- invoicing
- financial authority
- reporting/KPIs
- operational pressure visibility

Do not use this library to justify plugins, addons, marketplaces, integration ecosystems, bolt-on modules, white-label extensions, custom widget systems, advanced multi-shop enterprise tooling, optional feature packs, AI marketing pages, or peripheral ecosystem products.

We are studying:

- density
- hierarchy
- spacing rhythm
- review-first posture
- operational grouping
- scanability
- workflow pacing
- service-lane feel
- interaction sequencing
- advisor movement through the system

We are NOT copying:

- branding
- logos
- proprietary assets
- exact visual identity

## Reference Roles

Tekmetric references are primarily used for:

- operational grounding
- service-lane feel
- workflow posture
- dense operational rhythm

AutoLeap references are primarily used for:

- readability refinement
- calmer grouping
- cleaner workflow pacing
- estimate readability
- customer/vehicle clarity

ARK should increasingly feel:

- operational
- calm
- dense-but-readable
- service-lane oriented
- review-first
- workflow-driven

ARK should ultimately converge toward:

- Tekmetric operational grounding
- AutoLeap readability refinement
- ARK operational continuity architecture

Maintainers should use this library as operational UX reference authority when refining:

- dashboards
- queues
- estimates
- customer workflow
- vehicle workflow
- approval posture
- review/edit posture

Use both reference libraries when refining queues, dashboards, estimates, customer workflow, vehicle workflow, approval posture, and review/edit posture.

If a reference solved a real operational UX problem well, use the interaction pattern as grounding unless ARK already has a clearly superior operational behavior.

## Refinement Doctrine

Before changing an ARK operational surface, study the relevant reference folders first.

Default toward:

- operational familiarity
- believable service-lane rhythm
- workflow scanability
- dense-but-calm hierarchy
- review-first posture with intentional edit transitions

Do not invent a new UI language when existing shop software already shows a proven operational convention.

## Video Reference Doctrine

Video references exist to study operational motion:

- queue scanning cadence
- estimate mutation flow
- review/edit transitions
- approval sequencing
- customer and vehicle lookup behavior
- advisor pacing through daily shop work
- mobile service-lane movement

Study core daily shop operations only. Ignore plugins, addons, marketplaces, ecosystem integrations, AI upsells, and optional enterprise modules unless they directly reveal daily workflow pacing.

The library has enough coverage when:

- operational patterns become repetitive
- spacing rhythm becomes obvious
- hierarchy conventions become obvious
- workflow pacing becomes obvious
- queue rhythm becomes obvious
- estimate interaction posture becomes obvious
- CRUD/admin layout instincts are replaced by shop workflow instincts
- ARK consistently feels like real shop software
